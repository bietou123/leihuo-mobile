# 网络恢复与视频任务续查

更新日期：2026-10-22。对应版本：1.2.2。

## DNS 恢复

App 优先使用手机系统 DNS。仅对 `ai.leihuo.netease.com`，系统解析失败时先查手机上尚未过期的私有地址缓存，没有可用缓存再依次查询固定的 Cloudflare 和 Google HTTPS DNS 服务。每个备用查询的等待上限为 2 秒，两次查询合计约 4 秒；这个时间只指备用 HTTPS 查询，不包含之前的系统 DNS 查找及其他调度时间。解析响应最多读取 16 KiB。

缓存保存的是此前成功**解析**的地址，不表示已成功连接或通过 TLS 验证。地址保存在应用私有 SharedPreferences 中：系统解析结果缓存 60 秒；HTTPS DNS 结果取相关 A/CNAME 记录的最短 TTL，最多保留 15 分钟，不延长上游期限，TTL 为 0 时清除旧缓存且不缓存该结果。缓存地址不直接进入公开仓库、诊断文本或聊天记录；原生 DNS、超时、连接和 TLS 失败使用固定的分类说明，其他原生异常中的裸 IPv4 地址也会遮蔽。

备用解析不适用于官方管理端、任意用户填写的其他网关或媒体 CDN。DNS 查询不携带雷火 API Key、登录 Cookie、聊天正文或任务编号；备用解析器使用独立客户端，不自动携带 Cookie 或认证信息。每个备用解析器只发送一次查询，不自动跟随重定向或补发请求；不同调用不通过同一把锁串行等待网络。

使用备用或缓存地址时，请求的目标仍是原来的 HTTPS 网关域名；Host、TLS SNI 和证书域名校验保持一致。不能因域名解析失败而改用 HTTP、直接把私有 IP 显示给用户，或接受无效证书。

手机仍需连接能够访问网易内网的公司网络或 VPN。恢复 DNS 只解决域名到地址的解析，不能创建内网路由，不能代替 VPN，也不能保证手机当前网络可以到达网关。

## 已有视频任务的读取

视频提交成功后保存任务编号及查询配置。查询原任务使用 GET，首次读取等待上限为 60 秒；遇到可恢复的网络问题时，App 层额外最多重试 3 次，等待上限分别为 75、90、90 秒。因此一轮 App 读取最多包括原调用和 3 次额外调用，后续正常轮询重新从 60 秒开始。HTTP 客户端仍可能在同一次 GET/HEAD 内做协议允许的后续读取；不会据此创建生成任务，且该调用仍受 App 等待上限及取消控制。任务轮询受 20 分钟总等待期限限制。

短暂的超时、DNS、连接或读取失败，以及允许恢复的 HTTP 状态，只会重试读取原任务。TLS 证书或安全连接错误、本地参数校验和解析错误在 HTTP 状态判断之前排除，不参与 App 自动重试。提交生成的 POST 正文标记为一次性发送，HTTP 客户端禁止因连接失败、503 或 421 自动重放正文；App 也不会因查询失败切换协议或重发 POST 创建新任务。

暂停、重启或媒体地址失效后，可以继续查询同一任务。任务已完成但播放器未能读取文件时，重新读取视频地址同样只查询原任务。查询成功与手机能够播放文件是两个分别处理的状态。

## 复制错误信息

诊断包含版本、模型、阶段、请求方式、接口路径、任务状态、实际收到的 HTTP 状态、错误来源、允许复制的错误代码及净化后的原因。没有收到响应时，不用 HTTP 0 或假定的 200 代替真实状态。HTTP 200 的业务错误仍保留实际响应状态，原生网络错误单独记录来源与代码。

错误原因只从已知标量字段提取，不复制完整请求、响应、Headers 或 Cookie。真实网关密钥由原生桥遮蔽；URL、签名查询、认证信息、密码等赋值和多行 Base64 附件均隐藏。接口路径去掉查询参数及片段，任务编号在路径中使用占位符。净化失败时使用固定的通用说明。

## 当前证据与验证范围

本轮只读查询了用户已经提交的一个视频任务。网关返回 HTTP 200、任务成功状态及 HTTPS MP4 产物字段；这证明该已有任务的查询返回包含产物信息，不能据此宣称手机上的下载、播放或新的视频生成已验证成功。

本轮没有新建收费生成任务，没有运行测试，也没有进行手机真机验证。公开文档不记录实际任务编号、网关私有 IP、API Key 或签名媒体地址。DNS 恢复、GET 重试和错误诊断的实现仍需结合发布源码及手机实际网络确认。
