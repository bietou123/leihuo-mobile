# 综合记忆

`app/src/main/assets/memory.js` 提供本地跨对话记忆。模型、聊天窗口和模型供应商不作为记忆隔离边界。记忆保存为独立数据，不依赖原聊天继续存在。

## 保存内容

- 默认开启。首次启用版本会导入现有对话，之后增量保存每个对话中的用户文字、助手最终回复，以及已提取的文件文字。
- 图片、音频等附件仅保存名称，不保存二进制内容，也不凭附件名称推断视觉或声音信息。
- 不保存思考过程、正在流式生成的内容、被停止或中断的助手回复、报错回复、未完成的视频任务进度提示。
- 保留有效文字全文；条目数量没有自动淘汰上限，文件文字受现有附件解析流程的限制。
- 常见 API Key、Bearer 令牌、JWT、密码赋值、私钥等会在写入记忆前脱敏；原生层在读取、保存、导出及发送记忆上下文前，也会精确隐藏当前配置的网关密钥。格式检测不能识别一切秘密，用户仍可在记忆管理界面删除相应条目。
- 关闭综合记忆时保留已有条目，关闭期间的新消息加入忽略清单；重新开启后不会补录关闭期间的内容。

## 回忆方式

每次普通聊天请求在本机检索跨对话条目，将相关片段作为背景附到模型请求中。所有兼容聊天协议使用相同的记忆来源。用户手写长期备注优先，其次是与问题匹配的历史用户原话、明显的用户偏好和最近其他对话的上下文。条目明确标注“用户原话”或“助手回复”，避免将助手推测误当作用户事实。

中文按相邻两字、英文按词做文本匹配，不调用额外模型或向量接口。当前对话的条目不重复加入跨对话背景，因为当前对话已有历史请求。默认背景限长为 10,000 字符；检索背景中的片段可截取，保存的原文不会因此截短。较长历史不可能在每次请求中完整发送，相关记忆通过后续问题继续检索。

记忆检索与整理不产生额外模型请求。带记忆的普通聊天请求仍由网关正常计费，背景文字可能增加输入 token。记忆内容会随聊天请求发送给当前选择的模型；附件二进制不会由记忆模块再次上传。

## 数据与删除语义

```json
{
  "version": 1,
  "enabled": true,
  "notes": "用户手写备注",
  "entries": [
    {
      "id": "chat-id/message-id",
      "chatId": "chat-id",
      "messageId": "message-id",
      "role": "user",
      "text": "完整有效文字",
      "title": "原对话标题",
      "model": "原模型编号",
      "createdAt": 0,
      "updatedAt": 0
    }
  ],
  "ignored": []
}
```

删除对话不会删除已经保存的记忆。删除某条记忆或清空记忆会把相应消息 ID 加入 `ignored`，防止原聊天在下次保存时再次导入；清空还会覆盖当前已有对话的全部消息 ID 并清空手写备注。删除忽略记录后的新消息可以继续保存。

老版本消息没有单独的发送时间，首次导入时使用聊天创建时间与消息顺序作稳定兜底；新版本消息优先使用自己的时间戳。因此老历史的日期仅供参考。初始化或导入时会补齐缺失、重复的消息 ID 并保存，保证后续去重和忽略清单稳定。

原生存储使用应用私有目录中的独立 `memory.json` 和 `AtomicFile`，UTF-8 大小上限为 32 MB。读失败会返回错误并阻止自动空值覆盖；保存超限或失败保留原文件，由用户在记忆管理中导出和整理。综合记忆数据不放入开源仓库，也不会自动上传到 GitHub。

## 前端接口

- `normalize(value)`：返回规范化、脱敏后的标准 schema。
- `ingest(state, chats)`：增量更新并返回 `{state, changed}`。
- `context(state, {chatId, query, maxChars})`：返回供聊天请求使用的中文背景字符串，关闭时返回空字符串。
- `remove(state, id)`：移除条目并记录忽略 ID，返回状态。
- `clear(state, chats)`：清空并记录忽略 ID，返回状态。
- `exportData(state)`：返回标准 schema 的独立副本，可直接 JSON 导出。

除 `normalize` / `exportData` 外，修改接口会在合法状态对象上原地更新；调用者应采用返回的 `state` 并负责持久化。模块本身不读取网关凭据，不操作聊天数据，不发网络请求。
